# 顾客端 SSG / ISR 与动态预订：人工验收

正式网址：https://the-wild-oasis-website-ai.vercel.app

准备：一个普通浏览器窗口登录顾客账号，另一个无痕窗口保持未登录；打开 F12 → Network，勾选 Preserve log。默认使用现有演示账号和可用日期，避免修改真实客户资料。

## A. 公开页面与缓存

1. 无痕依次打开 `/`、`/about`、`/cabins`、任意 `/cabins/数字ID`。
2. 预期：首页/关于正常；列表显示房型与照片；详情先有介绍，预订区域独立加载当前日历。静态页面中不出现其他顾客姓名或头像。
3. Network 观察 Document：重复访问可见 CDN 缓存命中或再验证。`x-vercel-cache` / `x-nextjs-cache` 可能是 MISS、HIT、STALE；首请求 MISS 不是失败。Vercel 可能内部消费 `s-maxage`，浏览器不一定能看到原始 3600 秒，不能只据此判断 ISR 失败。构建清单与 `verify:rendering` 已独立验证一小时 ISR。
4. 如需验证静态 HTML，使用“查看网页源代码”：首页文案、列表房型卡、小屋介绍应存在，不是仅有浏览器加载后生成的占位。

## B. 列表筛选与浏览器导航

1. `/cabins` 点击 1–3、4–7、8–12 人筛选，再点击 All Cabins。
2. 预期：URL 的 `capacity` 更新，列表只显示相应容量，全列表恢复。
3. 复制筛选后的 URL 在新标签页打开，等待客户端挂载后仍匹配筛选；进入详情再后退，筛选与列表匹配。

## C. 登录状态与用户隔离

1. 无痕详情应显示登录提示，允许查看日历，但不显示可提交的预订表单。
2. 普通窗口完成 Google 登录，再进入详情：导航出现头像（账号有头像时），表单显示自己的姓名。
3. Network 的 `/api/guest/session` 应为 200，响应仅包含 `user.name` / `user.image`，或未登录的 `user:null`；响应头含 `private` 和 `no-store`，不能返回 email、guestId、凭据或完整 session。
4. 普通窗口退出登录，再返回详情或重新聚焦标签页，应恢复登录提示；无痕窗口始终不出现另一窗口的身份。
5. 记录通过/失败即可，不把个人响应原文、Cookie、Token 或真实姓名粘贴进验收报告。

## D. 实时库存、规则与报价

1. 详情 Network 的 `/api/cabins/ID/availability` 应为 200、`no-store`；返回当前价格/容量/规则与已占用日期，不含订单或顾客个人信息。
2. 选择未来可用入住日，再选择符合页面最少/最多晚数的退房日。
3. 预期：入住/退房展示一致，晚数与“退房减入住”一致，总价为当前每晚价乘晚数；人数选项不超过房间与全局限制。
4. 尝试跨过已占用夜晚，界面应拒绝；已有订单的退房日不应被无条件视为占用夜晚。无日期、非法晚数或已失效日期不出现可提交按钮。
5. 切到其他标签页再切回，Network 应重新请求登录状态和库存。最终提交还会再次取价与校验。

## E. 独立接口失败与恢复

1. Chrome/Edge DevTools → Network request blocking，添加 `*api/cabins/*/availability*` 并启用，重新加载详情。
2. 预期：照片与介绍仍存在，预订区显示错误/重试（客户端最长约 15 秒）；不显示可提交表单。
3. 关闭阻断，点击 Retry availability，日历和表单/登录提示恢复。
4. 单独阻断 `*api/guest/session*`：日历可加载，但登录区显示错误/重试，不把读取失败当作“已登录”；解除后 Retry login status 恢复。
5. 验收结束关闭 Request blocking。阻断造成的网络错误是预期模拟，不代表生产接口本身故障。

## F. AI 推荐预填回归

1. 打开 AI Concierge，给出明确的未来日期、人数和预算，例如“2027年6月10日入住、6月13日退房，2人，总预算1200美元，帮我选房”。若无库存，换一组可用日期。
2. 采用返回的一个方案，进入对应小屋详情。
3. 预期：日期和人数进入选择器/表单，所选月份正确；独立库存读取完成后显示当前报价。采用方案不等于已创建预订。
4. 当前库存不再可用时不能沿用旧推荐强行提交，用户需重新选日期。
5. 这一步会真实调用模型，仅按验收需要进行少量请求，不批量跑付费评测。

## G. 最终预订与个人中心

1. 用演示账号在可用日期选择合法人数，提交一次演示预订。
2. 预期：成功跳转确认页；个人中心出现正确房间、日期、人数与服务端金额；刷新后仍存在。
3. 无痕查看同一详情，重新读取日历后应反映新增占用。不要仅依据 ISR 房型介绍判断库存。
4. 只有演示预订才可用于测试，验收后按正常业务入口处理；无需批量下单或直接操作数据库。
5. 若额外检查价格篡改，提交中应不依赖浏览器 `totalPrice`，金额仍按服务端计算；并发互斥由现有数据库约束保证，本轮已有代码与离线回归证据，不要求人工批量竞争下单。

## H. 员工端与移动端回归

1. 员工端普通订单与房型页面、Copilot 应继续工作；本轮未修改员工端运行时代码和 AI 接口契约。
2. 手机或 DevTools 390px 宽度检查导航、日历、表单与 AI 预填，页面无横向溢出，字段/按钮可操作。
3. 员工修改公开介绍、照片或列表价格后，公共展示允许 ISR 延迟：过期后由请求触发再生成，不保证点击保存后立即更新。预订区与最终提交的当前价格/库存不等待该公共缓存。

## 结果记录

按 `A / B / C / D / E / F / G / H` 回复 PASS 或 FAIL。失败附页面路径、操作、实际表现和脱敏错误码；不要提供密码、Cookie、Token、完整用户资料。

发布后的自动只读检查不替代 C 的真实 Google 登录、F 的真实模型预填、G 的真实提交与个人中心确认。它们须由上述人工流程确认。
